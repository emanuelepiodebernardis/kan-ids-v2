# RAM500 v0.14.2 — повторить только ESP32-C3

Mega уже принята: `MEGA_RAM500_20260916T141149Z_f0665b8d` содержит все 15 успешных запусков. Повторять Mega и энергетические серии не требуется. Приёмка и значения Mega находятся в `accepted_mega/`.

C3 v0.14.1 завершила вычислительную часть первого запуска, но USB-отчёт оборвался на `RAM_RESULT board=c`. Числовых результатов и контроля C3 нет, поэтому серия C3 не принята. Конкретная низкоуровневая причина обрыва по имеющимся логам не установлена.

## Запуск

1. Сохраните старые папки и архивы. Распакуйте этот ZIP в `E:\KAN_IDS_PAPER1_SW_20260908`, чтобы появилась отдельная папка `KAN_IDS_RAM500_20260916_v0.14.2`.
2. Подключите напрямую по USB прежнюю ESP32-C3: `SER=10:00:3B:CB:8D:70`. FNB58 не нужен. Закройте программы, открывающие COM-порт платы.
3. Выполните в PowerShell:

```powershell
& 'E:\KAN_IDS_PAPER1_SW_20260908\KAN_IDS_RAM500_20260916_v0.14.2\START_C3.cmd'
```

4. Дождитесь итогового ZIP и пришлите его. Пакет сам собирает пять вариантов, проверяет бинарные файлы и выполняет три свежих запуска каждого. Номер COM определяется по плате автоматически. При остановке сохраняется ZIP с исходными байтами, включая незавершённую строку.

## Что изменено

C3 использует протокол v2 с уникальным токеном запуска. Измерения и флаги правильности сохраняются до передачи отчёта. Вывод выполняется небольшими порциями с ограниченными ожиданиями и уступкой процессора. При тайм-ауте принимающая программа может до двух раз запросить сохранённый отчёт командой RESULT. Она не запускает нагрузку повторно и не переподключает порт. После перезагрузки прежний токен недействителен.

Проверки стека и heap выполняются после сохранения основного результата. CHECK при повторном запросе возвращает ранее сохранённый контроль. Полный отчёт, совпадающий токен, 1500 сравнений на запуск и все числовые проверки по-прежнему обязательны. Повторное чтение не является дополнительным измерением. Если восстановление передачи не удалось, пакет останавливается; неполные данные не принимаются.

Модели и 500 подготовленных входов не меняются. Протокол Mega v1 сохраняется, но START_MEGA.cmd для уже принятой серии запускать не требуется.

## Область измерения

Показатели относятся к диагностической прошивке HW500. C3 сообщает lifetime watermark стека loop task; в него может входить предшествующая обработка INFO. Новая функция вывода отчёта выполняется после сохранения снимков и не заменяет их более поздними значениями. Heap и резерв стека задач перекрываются в учёте; складывать их как независимые компоненты нельзя. Это не доказанный глобальный worst-case Peak RAM и не память полноценной IDS.

Локальные проверки и ограничения перечислены в `validation/VALIDATION.json`. Целевые C3-сборки этой версии проверяются на вашем Windows до загрузки: локальный набор инструментов ESP32-C3 в среде подготовки отсутствует. Host-тесты не являются аппаратным измерением. Успех новой передачи требует подтверждения на вашей плате.

Подробная методология: `MEASUREMENT_SCOPE_RU.md`. Подготовка использует Python 3.11 (64 бит), PlatformIO 6.1.19, pyserial 3.5 и закреплённые версии инструментов; глобальный Python не изменяется.
